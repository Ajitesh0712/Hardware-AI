The approach

The course is Fundamentals of Computing for Data Science, so the examiner is grading the data work: how you understood, cleaned, explored, tested, engineered and modelled the data. The website matters because it proves the model is actually used, but it should not take over the talk.

Rule 170% data scienceAbout 10 of 14 minutes go to the seven notebooks, their numbers and plots. The website gets the rest.
Rule 2Notebooks firstPresent in pipeline order, 01 → 07, then show the website as the place where that pipeline's output is used.
Rule 3Numbers, not adjectivesSay “270 missing prices, median ₹649, p = 0.491, holdout R² 0.993”, never “the data was messy” or “the model is very accurate”.
Rule 4Name the limits yourselfSay the proxy target and the high R² caveat before the examiner asks. It shows you understand your own results.

The one-line story to repeat: “We built a data science pipeline on 5,010 Amazon products, and our website uses the same feature code and the trained model to rank live Amazon listings for a user's request.”

0:00–3:30 · Opening + Phases 1–2

Ananya: problem, data understanding, cleaning

Show

Slide: problem + two pipelines01_data_understanding.ipynb → missing-value table, “Phase 1 findings”02_preprocessing.ipynb → clean_price, clean_rating, clean_review_count

Say

  1. Problem. “Buyers compare hundreds of listings by price, rating and specs. Keyword search can't turn ‘a laptop for video editing’ into measurable needs. We treated this as a data science problem.”
  2. Two pipelines. “Offline, seven notebooks analyse a Kaggle dataset and train a model. Live, the website uses the same feature code and that model on current Amazon listings.”
  3. Dataset. “5,010 Amazon India products, 10 columns, all stored as text because of ₹ signs, commas and ‘out of 5 stars’.”
  4. Quality findings. “270 missing discount prices, 34 missing review counts, 31 missing actual prices. No exact duplicates, but 685 rows share a title. The category columns have only one value, so product type must come from the title.”
  5. Key insight. “review_rating is always a whole number from 1 to 5: it is one review's stars, not the product average. 74.5% are 5-star. We state this caveat throughout.”
  6. Cleaning. “We wrote cleaning functions for prices, ratings and counts. 18 counts said ‘FREE Delivery by Amazon’, so missing counts rose from 34 to 52. We did not invent values: we added missing-value flags, computed discounts only for the 4,740 rows with both prices, and kept all 5,010 rows.”

Hand-over: “With clean data, Pawni will show what the data looks like and what we tested statistically.”

3:30–6:00 · Phases 3–4

Pawni: EDA and statistics

Show

eda_outputs/02_price_distributions.png and 03_log_price_distributions.pngeda_outputs/04_rating_distribution.pngeda_outputs/07_correlation_heatmap.png04_statistical_analysis.ipynb → Mann–Whitney output

Say

  1. Prices are skewed. “Mean discount price is ₹3,078 but the median is ₹649; a few phones and laptops pull the mean up. That's why we also plot log prices, and why the median is the better typical value.”
  2. Ratings. “Ratings pile up at 5 (mean 4.49, skewness −2.33). Discounts are large: median 56%.”
  3. Correlation. “Discount price and actual price correlate at 0.96. Rating has almost no linear link with price, review count or discount. These are associations, not causes.”
  4. Outliers. “IQR flags 633 discount prices, but they are real premium products, so we investigated them instead of deleting them.”
  5. Hypothesis test. “Do heavily discounted products get different ratings? H₀: same distribution. We used Mann–Whitney U because ratings aren't normal. Two groups of 2,370, α = 0.05, p = 0.491, so we fail to reject H₀. The effect size is tiny (r = 0.009).”
  6. Significance vs importance. “Spearman shows rating vs number of ratings ρ = −0.086 with p < 0.001: significant only because n is large, not practically important.”

Hand-over: “Most useful information is hidden in product titles. Ajitesh will show how we turned text into features.”

6:00–8:00 · Phase 5

Ajitesh: feature engineering

Show

05_feature_engineering.ipynb → category counts, 13-check table, coveragephase_outputs/phase5_feature_coverage.pngOne live notebook cell (below)

Say

  1. Why. “Models need numbers, but RAM, storage and screen size are hidden in titles like ‘16GB DDR5 RAM, 1TB SSD, 15.6-inch 144Hz’.”
  2. Categories. “Ordered regex rules give each title a category. A laptop must name a laptop and list a processor plus RAM, storage or OS, so a ‘laptop backpack’ is an accessory. Unclear titles stay unclassified: 1,076 of 5,010.”
  3. Six specs, category-aware. “RAM, storage, battery, screen size, charging watts and refresh rate, only for product types where they make sense, so ‘15.6 inch’ on a bag isn't a screen size.”
  4. Validation. “13 hand-checked titles all pass, and no value is out of range. Coverage is low (RAM found in 245 rows) because titles omit specs; missing stays missing.”
  5. Same code live. Run the cell below: “This is the exact function the website uses on live Amazon titles.”

Live notebook cell (run from the “Data Science” folder, works without internet)

import sys; sys.path.insert(0, "..")
from backend.product_features import classify_product, extract_title_specs, product_features
from backend.ml_model import predict_score

title = 'Lenovo LOQ Intel Core i7-13650HX, NVIDIA RTX 4060 8GB, 16GB DDR5 RAM, 1TB SSD, 15.6" FHD 144Hz Gaming Laptop'
category = classify_product(title)
print(category)                                   # Laptops
print(extract_title_specs(title, category))       # ram 16, storage 1024, screen 15.6, refresh 144
product = {"product_title": title, "product_price": 89990,
           "product_star_rating": 4.3, "product_num_ratings": 250}
print(product_features(product))                  # the 16 model inputs
print(predict_score(product))                     # about 0.555
print(classify_product("Laptop Backpack for 15.6 inch Laptops"))   # Computer Accessories

Point out that discount_percent comes out missing: the live title has no original price, so the model's imputer fills it with the training median. That's a good, honest talking point.

8:00–10:30 · Phases 6–7 · and 13:00–14:00 close

Vedansh: model, evaluation, limitations

Show

model_outputs/phase6_model_comparison.pngmodel_outputs/final_evaluation.csv (or the table in notebook 07)model_outputs/phase7_residual_diagnostics.pngmodel_outputs/phase6_feature_importance.png

Say

  1. Target. “There's no ‘good product’ label, so we built a transparent proxy: 0.45 × rating/5 + 0.35 × scaled log review count + 0.20 × discount. It is a teaching target, not user satisfaction.”
  2. Leakage-free split. “Colour variants of the same product would leak between train and test, so GroupShuffleSplit keeps each product's listings together: 995 holdout rows, 3,223 train, 792 validation, zero shared groups. The imputer is fitted on training data only.”
  3. Comparison. “Against a mean baseline (RMSE 0.117): Linear Regression 0.027, Decision Tree 0.024, Random Forest 0.014. Random Forest wins and is saved with joblib.”
  4. Holdout. “Evaluated once on the holdout: MAE 0.0042, RMSE 0.0093, R² 0.993. Residuals centre on zero but spread more for low scores.”
  5. Say the caveat first. “R² is high because rating, reviews and discount are both inputs and target ingredients. Feature importance confirms it: rating 0.61, reviews 0.24, discount 0.14. So this shows a consistent pipeline, not recommendation accuracy, which is why the website uses the model only to break ties.”

Closing (13:00–14:00)

  • Limitations: single-review ratings, only 28 laptops, sparse specs, proxy target, live accuracy not measured, scraping can be blocked.
  • Ethics: low-volume scraping with no bypassing of robot checks, no personal data, API keys kept out of code, no invented reviews.
  • Next: save live listings to retrain on current data, collect human relevance labels for Precision@5 / NDCG, use an official product API.

Words to use and avoid

SayInstead of
“The model predicts a proxy score built from rating, popularity and discount.”“The AI knows which product is best.”
“Holdout R² is 0.993, which is expected because the target is built from the inputs.”“Our model is 99% accurate.”
“We found no significant difference (p = 0.491).”“Discounts don't affect ratings.”
“Rating and price are barely correlated in this sample.”“Price causes ratings to…”
“The live score is applied to Amazon data but not evaluated on it, because there are no labels.”“The model works perfectly on live data.”
“Missing values were kept and imputed with the training median inside the pipeline.”“We removed bad data.”

Never call a regression result “accuracy”: accuracy is a classification metric. Use MAE, RMSE and R².
