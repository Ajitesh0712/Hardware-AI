Terms to know first

Everyone should be comfortable with these before reading their module. They come up in every viva.

Regular expression (regex)
A text pattern. (\d{1,3})\s*gb\s*ram finds “16GB RAM” and captures 16. The project uses regex to read prices, specs, budgets and model names from text.
Web scraping
Downloading a web page's HTML and reading values out of it. We use requests to download and BeautifulSoup to find elements such as the title or price.
API and JSON
An API is a URL the web page calls to get data. Our Flask backend answers POST /api/recommend with JSON, a text format of keys and values that JavaScript can read.
Flask
A small Python web framework. A function marked @app.route("/api/recommend") runs every time that URL is called.
Feature
One numeric input to a model, for example ram_gb or price_log1p. Feature engineering turns raw text into such numbers.
log1p transform
log(1 + x). Shrinks huge values (₹1,27,999 or 4 lakh ratings) so they don't dominate. The “1 +” keeps zero valid.
Regression
Predicting a number instead of a class. Our model predicts a score between 0 and 1.
Proxy target
A stand-in label built by a formula, because the data has no true “how good is this product” column. Ours mixes rating, popularity and discount.
Random Forest
Many decision trees, each trained on random rows and features; their predictions are averaged. Usually more stable than one tree.
Imputation
Filling missing values before training. SimpleImputer(strategy="median") fills each gap with that column's median from the training data.
Data leakage
When information from the test data sneaks into training, making results look better than they are. Grouped splitting and fitting the imputer only on training data prevent it.
GroupShuffleSplit
A train/test split that keeps whole groups together. Colour variants of one phone always go to the same side, so the model is tested on truly unseen products.
MAE, RMSE, R²
MAE: average size of the error. RMSE: like MAE but punishes big errors more. R²: share of the variation explained (1 is perfect, 0 is no better than always guessing the mean).
Mann–Whitney U and Spearman ρ
Non-parametric statistics that work on ranks, so they don't need normally distributed data. Mann–Whitney compares two groups; Spearman measures a monotonic relationship.
joblib
Saves a trained Python object (our model pipeline) to a file and loads it back later, so the website never retrains.
Mocking
In tests, replacing a real service (Amazon, MySQL) with a fake that returns fixed data, so tests are fast and repeatable.

Viva questions for Ananya

Why are all 10 columns read as text?

Prices contain “₹” and commas, ratings contain “out of 5 stars” and counts contain commas, so Pandas cannot parse them as numbers. Stage 1 of preprocessing converts them.

Why did missing review counts go from 34 to 52 after cleaning?

18 cells had the text “FREE Delivery by Amazon”. They contain no number, so clean_review_count returns NaN for them. 34 + 18 = 52.

Why didn't you fill missing prices with the mean?

Filling would invent values and hide which products truly lacked data. We kept them missing, added indicator columns, and only computed discounts where both prices exist. The model later uses a median imputer fitted on training data only.

Why weren't IQR outliers deleted?

A very high price is usually a real premium product (a flagship phone), not an error. Deleting it would remove genuine data, so outliers were only investigated.

Why are repeated titles not treated as duplicates?

No row is an exact copy. Repeated titles often have different prices, ratings or links, so they are separate listings. Phase 6 handles them by keeping each product's listings on one side of the train/test split.

What does review_rating really measure, and why does it matter?

One sampled review's stars (always 1–5), not the product's average. Analyses and the model's “rating” feature therefore use a noisy single-review signal, and live Amazon ratings (averages) mean something slightly different.

How does “laptop under 50k” become a budget?

parse_budget_limits matches “under” followed by a number and optional “k”, “thousand” or “lakh”, multiplies (50 × 1,000) and returns budget_max = 50000.

Why not rely only on Gemini to understand queries?

An API can be unavailable, slow or unconfigured, and an LLM can return inconsistent JSON. Category, budget, models and uses come from deterministic rules so results are predictable; Gemini only adds extra interpretation when a key exists.

How does review_themes decide praise or complaint?

It splits each review into parts, finds aspect words (battery, screen, heat…), then looks for negative cues (bad, issue, drains) or positive cues (good, smooth, great). With no cue it uses the review's stars: 4–5 praise, 1–2 complaint.

Why is the review text HTML-escaped?

The page inserts these lines as HTML. Escaping turns “<script>” into harmless text, so a malicious review or spec value cannot run code in the user's browser.

Notebook 03: exploratory data analysis

Ten plots saved in Data Science/eda_outputs/: category bar chart, raw and log price histograms, rating count plot, discount histogram, four box plots, Pearson correlation heatmap, two scatter plots and median price by category. Main findings:

  • Prices are right-skewed: mean ₹3,078 vs median ₹649 (a few phones and laptops pull the mean up).
  • Ratings cluster at 5 (mean 4.49). Median discount ≈ 56%. Review counts range from 1 to 437,651 (median 2,321).
  • Correlations: discount price vs actual price r = 0.96; rating vs price, review count and discount ≈ 0; discount % vs discount price r ≈ −0.31. Correlation is not causation.
  • 27 inferred categories; 1,076 titles unclassified; laptops have the highest median price (₹41,240).

Notebook 04: statistical analysis

  • Descriptive table: mean, median, mode, variance, standard deviation, skewness, IQR. Skewness: discount price 6.74 (long right tail), rating −2.33 (piled at the top).
  • IQR outliers: 633 discount prices (13.4%), 632 actual prices (12.7%), 681 review counts (13.7%); flagged, not deleted.
  • Spearman correlation (spearmanr): rating vs discount price ρ = −0.015 (p = 0.31), vs discount % ρ = 0.018 (p = 0.22), vs number of ratings ρ = −0.086 (p < 0.001, significant but tiny).
  • Mann–Whitney U (mannwhitneyu): split at median discount into two groups of 2,370. H₀: same rating distribution. α = 0.05. U = 2,833,249.5, p = 0.491, rank-biserial r = 0.009 → fail to reject H₀.
  • Rank-biserial effect size = 2U/(n1·n2) − 1; positive means the high-discount group is rated slightly higher.

Viva questions for Pawni

Why use a log scale for price histograms?

Prices are heavily right-skewed. On a log scale the many cheap items and the few expensive ones are both visible.

What does a skewness of 6.74 for discount price tell you?

The distribution has a long right tail: most products are cheap and a few are very expensive. That is why the mean (₹3,078) is far above the median (₹649), and the median is the better “typical” value.

Why Mann–Whitney instead of a t-test?

Ratings are bounded, discrete and not normal (most are 5). Mann–Whitney compares ranks and does not assume normality.

State your hypotheses and conclusion.

H₀: high- and low-discount products have the same rating distribution; H₁: they differ. With α = 0.05 and p = 0.491 we fail to reject H₀: no evidence of a difference. That does not prove they are identical, and it says nothing about cause.

The Spearman result for reviews vs rating was significant. Is it important?

No. ρ = −0.086 is tiny; it is significant only because n ≈ 5,000. Statistical significance is not practical importance.

Why use Spearman as well as Pearson?

Pearson measures straight-line relationships and is sensitive to skew and outliers. Spearman uses ranks, so it suits skewed prices and bounded ratings.

How does the chat know “under 70000” is a refinement but “ps5” is a new search?

“under 70000” has no product words, only a budget, so it refines. “ps5” is a product word that was not in the previous search, so it starts a new search and drops the old RTX filter.

Why normalise “PlayStation 5” to “ps5”?

Users and titles use both spellings. Normalising both sides makes the match work either way.

Where does the badge colour come from?

The page colours the gauge from match_score (>80 green, >50 amber, else red). The backend sends match_score = fit × 10, so 9–10 shows green, 6–8 amber, ≤5 red.

Why does the page send currentRequirements with every follow-up?

The backend is stateless: each request is independent. The page sends the previous requirements so the backend can merge them with the new message.

Viva questions for Ajitesh

Why is feature extraction category-aware?

“15.6 inch” in a laptop backpack title is not a screen size, and “65W” in a phone title is charging power only near words like “charging”. Gating by category and nearby words prevents such false features.

Why was the laptop rule changed to need a processor plus RAM/storage?

Before, 155 of 188 “laptops” in the training data were bags, tables and mice that mention “laptop”, and real laptops with “DDR5” were labelled components. The stricter rule fixed both.

Why is spec coverage so low, and is that a problem?

Many titles don't list RAM or screen size (RAM found in 245 of 5,010 rows). Missing values are kept as missing and imputed inside the model pipeline. The model's importance for these specs ended up near zero.

How are training and live features kept consistent?

Both call product_features(), which accepts both column naming styles, and the model stores its feature order. Live products go through exactly the same code as Kaggle rows.

Why did follow-up searches once return nothing even though Amazon had products?

Amazon changed its layout so the first <h2> held only the brand. The scraper read “Apple” as the title, so no title contained “M5” and the exact-model filter removed everything. _read_title() now takes the full heading.

How do you avoid getting blocked by Amazon?

Short queries, a 15-minute cache for repeated searches, a 1-second gap between result pages, product pages only for the top 3 and one at a time, and a 10-minute pause after any robot check. We never try to bypass the check.

Why are missing ratings stored as None instead of 0?

0 would mean “zero stars” and would wrongly lower scores; it would also show “0 ratings”. None lets the page say “rating unavailable” and the model's imputer handle it.

What does the popularity score fix?

A product with 2 ratings averaging 5.0 would otherwise beat one with 2,000 ratings averaging 4.5. The weighted average pulls low-count products toward the overall mean.

Is scraping Amazon allowed?

Amazon's Conditions of Use restrict automated data gathering. We use it only for a low-volume academic demo with politeness rules; a real deployment should use an official product API.

How do the tests run without Amazon or MySQL?

unittest.mock.patch replaces search_products with FakeStore.search, which returns a fixed catalogue, and replaces the review and database functions with fakes. Gemini is switched off by clearing its key.

Notebook 06: model development

  • Target (0–1): 0.45 × rating/5 + 0.35 × log1p(reviews)/max + 0.20 × discount/100. A proxy for quality, popularity and discount, not user satisfaction.
  • Split: product_group() takes the text before the first “(”, “,” or “|”, so colour variants stay together. Holdout 995 rows; development 4,015 → train 3,223 / validation 792. Zero shared groups. Target constants come from development rows only.
  • Models (scikit-learn pipelines with median imputer): mean baseline, Linear Regression (+ scaler), Decision Tree (depth 8, 10 per leaf), Random Forest (300 trees).
  • Validation RMSE: Random Forest 0.0140 · Decision Tree 0.0237 · Linear 0.0270 · baseline 0.1171. Random Forest is refitted on all development rows and saved with joblib.dump together with its feature list, target settings and split settings.
  • Feature importance: rating 0.61, log reviews 0.24, discount 0.14; specs ≈ 0, because the target is built from those three.

Notebook 07: evaluation

Rebuilds the same split from the saved settings and evaluates once on the holdout: MAE 0.0042, RMSE 0.0093, R² 0.993 (development: 0.0027, 0.0063, 0.997). Residuals are centred on zero but wider for low predicted scores (< 0.6). Accuracy is not used because it is a classification metric.

Viva questions for Vedansh

Why is the target called a proxy, and what is its weakness?

The data has no true label for product quality, so we built one from rating, popularity and discount. Because those same signals are model inputs, the model mostly learns its own formula; the high R² shows consistency, not real recommendation accuracy.

Why GroupShuffleSplit instead of train_test_split?

The same product appears several times (colour variants). A random split would put variants in both train and test, which leaks information. Grouping by base title keeps each product on one side.

Why is the imputer inside the pipeline?

So its medians are learned from training rows only. Fitting it on all data would leak test information.

Why did Random Forest win?

It had the lowest validation RMSE (0.0140). Averaging many trees captures non-linear patterns better than Linear Regression and is more stable than one tree.

Explain MAE vs RMSE using your numbers.

Holdout MAE 0.0042: average error is about 0.004 on a 0–1 score. RMSE 0.0093 is larger because it squares errors, so the few bigger misses (low-score products) count more.

Why evaluate on the holdout only once?

If we kept checking the holdout and adjusting the model, we would be tuning on it, and its score would no longer be an honest estimate of performance on unseen products.

Why is the model only a tie-breaker in ranking?

It predicts a popularity/discount proxy, not whether a product meets the user's needs. Live data also differs (average ratings, missing original price). So explicit requirement checks set the main order.

How does the 1–10 match score work?

Each stated need is a weighted check scored 0–1 (type, model, budget, RAM, storage, GPU/CPU/battery for the use). Score = 1 + 9 × weighted share met, rounded. A laptop that clearly fails a key need is capped at 5.

Walk us through what happens in recommend_products.

Read JSON → parse requirements → decide category → build a short search query → search Amazon (with one retry) → process and rank → add badges → explain the top 3 → write summary → save to MySQL if available → return JSON. Errors return 400/404/502/503.

Why return 503 for a block but 404 for no products?

A block means we could not see Amazon, so we can't claim nothing exists; 503 tells the user to wait. 404 means Amazon answered and genuinely had no matching listings.

Team viva: questions anyone may get

Explain your project in one minute.

ElectronicsAI recommends electronics from a plain-English request. Offline, we cleaned and analysed a 5,010-product Kaggle dataset, engineered features from titles, and trained a Random Forest on a proxy score. Live, we scrape Amazon India, extract the same features, filter by category, model and budget, score each product out of 10 against the user's needs, use the model to break ties, and explain the top results with real specs and reviews.

Is the real Amazon data passed through your trained model?

Yes, every live product is scored by the Kaggle-trained model using the same feature code. But it is scoring, not evaluation: Amazon gives no correct answer to compare with, so the model's accuracy on live data is not measured. Its score only breaks ties.

Your R² is 0.993. Isn't that suspicious?

It is expected, not a sign of a great recommender. The target is a formula of rating, reviews and discount, and those are inputs, so the model reproduces its own formula. We used grouped splits so this isn't leakage of duplicate products.

Which FCDS phase did each of you do?

Ananya: 01 understanding and 02 preprocessing. Pawni: 03 EDA and 04 statistics. Ajitesh: 05 feature engineering. Vedansh: 06 model development and 07 evaluation. Each of us also built the website part that uses our phase.

What would you improve with more time?

Save live listings to build a current dataset and retrain; collect human relevance labels to measure Precision@5 and NDCG; use an official product API instead of scraping; read the original price live so the discount feature isn't imputed.

What are the main limitations?

Single-review ratings in training data, few laptops (28), sparse specs in titles, a proxy target, scraping that can be blocked, and rule-based text analysis that can misread some reviews.

Where is data science used, and where are rules used?

Data science: cleaning, EDA, statistics, feature engineering, model training and evaluation (notebooks), and the model score live. Rules: parsing requests, filters, the 1–10 match score and the explanations, because they must be transparent and follow the user's stated needs exactly.

How did you test the system?

46 automated tests with Flask's test client and mocked Amazon, Gemini and MySQL, covering parsing, chat follow-ups, filtering, ranking, insights and every error path. Separately, a few live searches on Amazon India.

What ethical issues did you consider?

Respecting Amazon's rules with low request volume and no bypassing of checks, keeping API keys out of code, collecting no personal data, being clear that scores are not guarantees, avoiding popularity bias in the main ranking, and never inventing reviews.

What happens if Gemini or MySQL is unavailable?

Gemini: the local rule-based parser is used. MySQL: saving is skipped and searching works normally.
